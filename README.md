# Tabloom

Tabloom 是一个供公司内部使用的 Chrome 标签分组插件。它直接编辑 Chrome 原生标签组：可以纯手动拖动整理，也可以使用自己配置的 OpenAI-compatible 模型生成可编辑建议。

## 安装

1. 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本仓库根目录 `chrome-ai-tab-grouper`。
5. 固定 Tabloom 图标；点击图标会打开 Chrome 侧边栏。

最低支持 Chrome 114。

## 手动使用

- 面板会读取当前窗口中的未分组标签和已有原生分组。
- 所有分组默认展开。
- 把标签拖到其他组或“未分组”区域，组内也可调整顺序。
- 可以新建、删除、重命名分组并选择 Chrome 原生颜色。
- 点击“重置”放弃尚未保存的调整。
- 点击“保存调整”后才会修改 Chrome。
- 顶部撤销按钮可恢复最近一次保存前的分组。

固定标签保持原位，第一版不会对其进行分组。

## AI 整理

AI 完全可选。点击设置图标填写：

- Base URL：DeepSeek 示例为 `https://api.deepseek.com`，默认模型为 `deepseek-v4-flash`。
- 模型名称：填写接口当前支持的模型名。
- API Key：默认只保留到浏览器会话结束；勾选后可保存在当前浏览器的扩展本地存储。
- 思考模式：默认开启并使用 DeepSeek `low` 强度，以提高标签归类成功率；可手动关闭以缩短响应时间。
- 开发者模式：在当前 AI 浮窗中临时显示模型的原始响应和解析错误，不显示 API Key，也不持久化调试内容。
- 整理偏好：例如“优先按项目分组，localhost 和 staging 放在一起”。

本地 OpenAI-compatible 服务可使用类似 `http://localhost:11434/v1` 的地址，并允许不填写 Key。Chrome 会在首次保存接口地址时请求该 origin 的访问权限。

三种策略：

- 整理未分组：尽量保留已有组。
- 优化已有组：允许合并、拆分和改名。
- 全部重组：忽略现有结构重新规划。

模型只收到标签 ID、标题、URL、当前组名与整理偏好，不读取网页正文。AI 返回的方案会经过标签 ID 完整性校验；失败时不会覆盖当前草稿。整理期间可点击状态浮窗查看进度；思考模式开启时会显示模型接口返回的推理内容。AI 整理后仍保留“未分组”区域，并且底部按钮保持不变，可切换策略再次整理。

## 开发与验证

项目无运行时依赖，也不加载远程 JavaScript。

```bash
npm test
npm run verify
```

`npm test` 使用 Node 内置测试运行器验证草稿、拖动状态、保存计划、Chrome API 网关、模型配置与 AI 响应校验。`npm run verify` 检查 Manifest、入口文件、权限以及远程/内联脚本。

## 当前限制

- 只处理当前 Chrome 窗口，不跨窗口移动标签。
- 不读取网页正文，不支持嵌套标签组。
- Service Worker 重启后，“撤销上次保存”的内存快照会丢失。
- 需要在真实 Chrome 中加载后才能完成原生标签组的人工验收；普通网页预览无法访问 `chrome.tabs` 和 `chrome.tabGroups`。
